# Підбір страв за продуктами

## Purpose

Показувати рецепти, у яких використовується хоча б один продукт, вибраний користувачем із каталогу доступних продуктів.

## Routes

- /cook — одноразовий підбір страв.
- GET /api/recipe-suggestions?productIds=id1,id2 — read-only список рецептів.

## Flows

1. Відкрити «Що приготувати?».
2. Знайти продукти через пошук і вибрати один або кілька checkbox-контролів.
3. Переглянути рецепти, що мають хоча б один збіг.
4. Відкрити картку рецепту; повернення зберігає вибрані продукти через URL.
5. Очистити вибір і почати новий підбір.

## Desktop UI

Сторінка має дві колонки: sticky-панель вибору продуктів і область результатів зі стандартною сіткою recipe-карток. Власний пункт є в desktop-навігації.

## Mobile UI

Панелі складаються вертикально. Сторінка доступна з розділу «Ще», щоб нижня навігація зберігала п’ять основних пунктів.

## Actions

Пошук продукту, вибір/скасування вибору, очищення всіх вибраних продуктів і відкриття рецепту.

## State and storage

Постійний інвентар і кількості не зберігаються. Вибрані product IDs живуть у параметрі productIds URL лише для навігаційного контексту та відновлення сторінки.

## Validation

Endpoint вимагає непорожній список product IDs, відхиляє порожні елементи та дедуплікує значення. Користувачеві доступні лише активні продукти; архівні рецепти не повертаються.

## UI states

Loading продуктів або результатів, помилка з повторною спробою, відсутність продуктів у каталозі, порожній вибір, відсутність збігів і готовий список рецептів.

## Accessibility

Пошук має доступну назву, продукти представлені native checkbox-контролами з видимими підписами, вибрані продукти можна скасувати клавіатурою, а всі посилання та кнопки мають видимі focus-стани.

## Tricky cases

- Пошук продуктів не скидає вже вибрані значення.
- Невідомі або пошкоджені URL-значення не запускають запит рекомендацій.
- Зміна рецептів або продуктів підхоплюється через стандартне кешування та інвалідацію catalogue-даних.

## Acceptance criteria

- Без вибраних продуктів рецепти не завантажуються.
- Один або кілька вибраних продуктів повертають рецепти з будь-яким збігом інгредієнта.
- Результати відсортовані за назвою і використовують стандартні recipe-картки.
- Архівні продукти не можна вибрати, архівні рецепти не з’являються.
- Перехід у деталі та повернення зберігають productIds.

## Tests

Unit-тести нормалізації ID та збігу; repository/API-тести запитів ingredient-зв’язків; component-тести вибору, URL-стану, пошуку, loading/error/empty/no-results і доступності.

## Dependencies

Products, recipes, authenticated API repository, shared async states, recipe-card media and application navigation.

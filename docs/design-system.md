# Design system

Meal Planner uses a Nordic editorial visual language: Newsreader for display headings and Manrope for interface copy. Semantic colours are defined in `src/styles/tokens.css` and are applied through the `data-theme="nordic"` contract on the root document. Text and controls must meet WCAG 2.2 AA contrast.

## Theme tokens

All visual colours belong in `tokens.css`. Components and feature styles must use semantic custom properties rather than hex, RGB, HSL, `color-mix`, or theme-specific fallback values. The token contract includes canvas and surfaces, text and muted text, borders, primary/accent and their states, danger/success/warning/focus, overlays, translucent surfaces, gradients, shadows, calendar states, illustration colours, and image-editor colours. A future palette is added as a new `[data-theme="theme-name"]` block without changing feature CSS or React components.

Keep foreground/background pairs contrast-safe for WCAG 2.2 AA. Focus indicators, disabled states, selected states, and overlays must remain distinguishable without relying on colour alone.

Spacing follows a 4/8 px rhythm. Standard radii are 12, 20, and 28 px. Touch targets are at least 44 by 44 px. Shadows are restrained and never the sole boundary. Lucide icons replace text glyphs and always have either a visible label or an accessible name.

Shared primitives own buttons, button-links, fields, async comboboxes, dialogs/drawers, action menus, segmented controls, calendar selectors, toasts, banners, skeletons, empty/error states, confirmations, date-range controls, and navigation headings. `Button`, `ButtonLink` and `IconButton` own the common action variants and 44 px target; `FormActions` standardizes cancel/save states for inline editors. `FormField` is the canonical label, hint, validation and required/optional treatment for form controls; `PasswordField` adds the accessible show/hide affordance; `SearchField` standardizes labelled search inputs with the leading icon; `ChipGroup` owns filter and category chips with `aria-pressed` state. `Alert` owns error, success, warning and info feedback semantics; `MediaPlaceholder` owns image failure and missing-media fallback rendering. All routed screens use `PageHeader` for their primary `h1` (eyebrow, description, and actions) and `SectionHeading` for repeated `h2` blocks. `BackLink` owns the shared icon-and-label alignment for contextual navigation. `Dialog` owns modal semantics, backdrop dismissal, Escape handling, focus trapping, and focus restoration; feature dialogs provide only their content and actions. `LoadingState`, `RetryBanner`, and `EmptyState` keep asynchronous feedback consistent across server-backed screens. The canonical page title uses the global Newsreader scale `clamp(2.35rem, 5vw, 4.6rem)`; a larger title is reserved for a detail hero, not a page shell. Every interactive element has visible focus; motion respects `prefers-reduced-motion`; loading, empty, stale, offline, error, and success states use consistent copy and placement.

Recipe photography has one canonical 4:3 composition. The crop editor produces that composition once; catalogue cards, recipe detail, planner picker, and day/week planner cards reuse it through the shared `recipe-media-4x3` contract without feature-specific recropping or stretching. Legacy non-4:3 assets use a centered `object-fit: cover` fallback until the user re-edits them. Missing and failed images use `MediaPlaceholder` in the same 4:3 footprint so layout does not shift.

Planner and shopping views prioritize date, recipe, servings, product, quantity, and unit. Avoid language implying stock, cooking completion, or purchases because shopping remains a read-only demand projection.
